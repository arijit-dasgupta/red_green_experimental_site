# Red-Green Experiment 1 Dataset

This folder contains the preregistered stimulus set for the Red-Green Human Study (Experiment 1).

## Folder structure

Each trial has its own folder, named by trial ID, for example `T1A/`, `T9/`, or `T30/`. The six familiarization trials are `F1` to `F6`, and they follow the same folder structure as the experimental trials.

Inside each trial folder:

- `init_state_entities.json`: the initial scene state. This is the less important file for analysis; it records the starting positions, sizes, and directions of the ball, barriers, occluders, and goal sensors.
- `simulation_data.json`: the full physics rollout. This is the main trial file. It stores the scene geometry, simulation parameters, and the ball trajectory frame by frame as generated by the Pymunk simulation (`pymunk v6.9.0` on Python).
- `{trial_id}_stimulus.mp4`: the rendered stimulus video for that trial. This is what participants would see, at the same frame rate (30 FPS).

At the top level, the folder contains 62 unique trial directories. After applying the repetition schedule in `repeat.csv`, these expand to 74 experimental trials in the actual experiment.
The familiarization trials also included and follow the same folder structure, even though they are not part of the 74 experimental trials counted above.

## Metadata files

- `trial_label.csv`: maps selected trial IDs to stimulus-set tags. Not every trial is tagged, only the ones with a specified stimuli set.
  - `Initial Direction`: `T1A` to `T3D`
  - `Path Visibility`: `T4A` to `T5F`
  - `Occlusion Window`: `T6A` to `T8D`
  - `Practice Effects`: `T9`, `T10`, `T11`
- `repeat.csv`: practice-effects schedule. For each listed trial, the number specifies how many times to repeat it after its first appearance, so total appearances = `1 + repeat count`.
- `catch_trials.txt`: one catch trial ID per line.
  - Catch trials: `T30`, `T31`, `T32`, `T33`, `T34`

## Simulation schema

`simulation_data.json` is the main source for reconstructing each trial. It is a JSON object with:

- `barriers`: rectangle geometry for all barriers in the scene
- `occluders`: rectangle geometry for all occluders
- `target`: the ball shape metadata, including its size
- `red_sensor` and `green_sensor`: goal-region rectangles
- `scene_dims`: world width and height
- `interval`, `friction`, `elasticity`: simulation constants used by the `pymunk` physics engine
- `timestep`, `timesteps_per_frame`, `num_frames`, `fps`: timing and frame-count settings. Note that a timestep denotes the physics simulation timestep, but a frame denotes the point in time where the physical motion is recorded as a frame in the video (to be played back at 30 FPS). We use several `timesteps_per_frame` to ensure accurate physical simulation.
- `step_data`: frame-by-frame ball state, keyed by frame index
  - each frame stores `x`, `y`, `speed`, `dir`, `vx`, and `vy`
- `rg_outcome` and `rg_hit_timestep`: the first goal reached and the frame when it was reached
- `num_barriers` and `num_occs`: counts of barriers and occluders

This JSON file is also used directly by the human experiment website to render the trial on a JavaScript canvas element at 30 FPS. We do not rely on the MP4 alone for data collection, because the canvas-based rendering lets us record `f` and `j` keypresses frame by frame with precise synchronization before the next refresh.

`init_state_entities.json` stores the starting scene before simulation. Each entity includes an `id`, `type`, `x`, `y`, `width`, `height`, and, for the ball, an initial `direction`.
